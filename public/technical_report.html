1. Selection of Technology and Justification

The technology stack for Kretabazaar was strategically selected to guarantee maximum loading performance, developer productivity, type safety, and serverless scalability:

Frontend: Next.js 15 & React 19

Hybrid SSR/SSG rendering model, Server Components, and Turbopack bundler for sub-second page loads and dynamic SEO optimization.

Styling: Tailwind CSS v4

Utility-first atomic CSS framework compiling into minimal CSS sheets with responsive dark/light mode and glassmorphism styling.

Database ORM: Prisma 6 & SQLite/PostgreSQL

End-to-end type-safe database queries, zero-config local SQLite testing, and seamless migration path to cloud PostgreSQL.

Payments: Stripe SDK & Webhooks

PCI-DSS compliant tokenized card processing, checkout sessions, and cryptographic webhook signature verification.

2. Problem and Weaknesses of Legacy Systems

System Area Legacy Monolithic System Weakness Kretabazaar Platform Solution
Performance & Latency High Time To First Byte (TTFB), heavy PHP execution, 3s+ load times. Next.js 15 App Router Server Components with sub-second response times.
Inventory & Concurrency Race conditions causing overselling during flash sales. Atomic Prisma ORM database transactions on verified Stripe webhooks.
Cart Persistence Fragile PHP cookies cleared when switching devices or closing tabs. Dual Cart System: Cookie session tokens merged into user cart upon login.
Logistics Tracking Opaque shipping requiring support emails or third-party sites. Integrated /api/orders tracking API with 4-step real-time progress bar.

3. Technology and Literature Review

Modern e-commerce has evolved from monolithic PHP setups to Jamstack Headless Architecture. By decoupling the presentation layer (React 19) from the backend API services (Next.js Route Handlers) and payment engines (Stripe API), Kretabazaar eliminates single points of failure, accelerates global distribution via Edge CDNs, and guarantees security.

6. Database Design & Entity Relationships

Key entities and relationships implemented in prisma/schema.prisma:

  • User & Address: 1-to-Many relationship for shipping and billing addresses.
  • Category & Product: 1-to-Many relationship grouping products under categories (Apparel, Electronics, Digital, Accessories, Audio).
  • Product & ProductVariant: 1-to-Many relationship defining SKU variations (colors, sizes, price offsets).
  • Cart & CartItem: 1-to-Many relationship supporting guest session tokens and authenticated user accounts.
  • Order & OrderItem: 1-to-Many relationship tracking total amounts, carrier tracking numbers, and fulfillment status.
